# TensorAlgebra Fold Bridge Plan

## Motivation

`Fold.fold_eq_vector_map` exposes tensor update results through an existential:

```lean
if h : ∃ i, ∃ hi, imap i hi = j then
  let i := choose h
  ...
else
  ...
```

This is awkward downstream because proofs must reason about `Classical.choose h`, where `h` is often
the hidden proof generated by an `if`/`dif` branch. This made full-layout lemmas for TensorAlgebra
unnecessarily noisy.

The proposed `Fold.fold_eq_vector_map'` is a better theorem shape:

```lean
if h : j ∈ Set.range (fun i : {i' // i' ∈ range} => imap i.1 i.2) then
  let ⟨i, hi⟩ := invFun (fun i : {i' // i' ∈ range} => imap i.1 i.2) j
  f i hi xj
else
  xj
```

This replaces arbitrary existential witnesses with inverse-function witnesses. For tensor layouts,
we should bridge that inverse-function API to the existing `FinHTupleMap.rangeInv` and
`FinHTupleMap.rangeNatInv` API.

## Required Bridge API

Add layout/index-function bridge definitions, probably in `Data/FinHTuple/FinHTupleMap.lean` or a
small helper namespace imported by tensor algebra proofs.

For scalar-destination layouts:

```lean
def FinHTupleMap.indexFun {src : HTuple Nat p} {n : Nat}
    (map : FinHTupleMap src h(n)) :
    {i' // i' ∈ ((0 : HTuple Nat p)...src)} → Nat :=
  fun i => (map i.1).toScalar
```

For general-destination layouts:

```lean
def FinHTupleMap.tupleFun {src : HTuple Nat p} {dst : HTuple Nat q}
    (map : FinHTupleMap src dst) :
    {i' // i' ∈ ((0 : HTuple Nat p)...src)} → HTuple Nat q :=
  fun i => map i.1
```

Then prove injectivity bridges:

```lean
theorem FinHTupleMap.indexFun_injective
    {map : FinHTupleMap src h(n)} (hmap : map.Injective) :
    Function.Injective (map.indexFun)

theorem FinHTupleMap.tupleFun_injective
    {map : FinHTupleMap src dst} (hmap : map.Injective) :
    Function.Injective (map.tupleFun)
```

Bridge range membership:

```lean
theorem FinHTupleMap.mem_rangeNat_iff_mem_range_indexFun
    (map : FinHTupleMap src h(n)) (j : Nat) :
    j ∈ map.rangeNat ↔ j ∈ Set.range map.indexFun

theorem FinHTupleMap.mem_range_iff_mem_range_tupleFun
    (map : FinHTupleMap src dst) (j : HTuple Nat q) :
    j ∈ map.range ↔ j ∈ Set.range map.tupleFun
```

Bridge `invFun` to existing inverse APIs:

```lean
theorem FinHTupleMap.invFun_indexFun_eq_rangeNatInv
    (map : FinHTupleMap src h(n)) (j : Nat)
    (hj : j ∈ map.rangeNat) :
    invFun map.indexFun j =
      ⟨(map.rangeNatInv j hj).val, FinHTuple.val_mem_zero_shape _⟩

theorem FinHTupleMap.invFun_tupleFun_eq_rangeInv
    (map : FinHTupleMap src dst) (j : HTuple Nat q)
    (hj : j ∈ map.range) :
    invFun map.tupleFun j =
      ⟨(map.rangeInv j hj).val, FinHTuple.val_mem_zero_shape _⟩
```

If subtype equality is cumbersome, prove evaluation-oriented versions first:

```lean
theorem FinHTupleMap.indexFun_invFun_eq
    {map : FinHTupleMap src h(n)} (hmap : map.Injective)
    {j : Nat} (hj : j ∈ Set.range map.indexFun) :
    map.indexFun (invFun map.indexFun j) = j

theorem FinHTupleMap.tupleFun_invFun_eq
    {map : FinHTupleMap src dst} (hmap : map.Injective)
    {j : HTuple Nat q} (hj : j ∈ Set.range map.tupleFun) :
    map.tupleFun (invFun map.tupleFun j) = j
```

## TensorAlgebra Vector Theorem Shape

Once the bridge API exists, add primed vector implementation theorems that expose layout range APIs
directly.

For `tensorAxpy`:

```lean
theorem Vector.tensorAxpy_eq_map' ... :
  tensorAxpy a xs xmap ys ymap hymap =
    ys.mapFinIdx fun j yj _ =>
      if hj : j ∈ ymap.rangeNat then
        let i := ymap.rangeNatInv j hj
        yj + a * xs[xmap i]
      else
        yj
```

Analogous theorem variants:

```lean
Vector.tensorScal_eq_map'
Vector.tensorMul_eq_map'
Vector.tensorSub_eq_map'
Vector.tensorNeg_eq_map'
Vector.tensorDiv_eq_map'
Vector.tensorInv_eq_map'
```

`tensorGemv_eq_map'` may also benefit from the same style for row-output layouts.

## Full-Layout Consequence

For rank-1 full layouts use `Layout.id h(n)` directly. `Layout.rowMajor h(n)` is definitionally equal
to identity:

```lean
example (n : Nat) : Layout.rowMajor h(n) = Layout.id h(n) := by rfl
```

The full-get proofs should then reduce to:

```lean
rw [LawfulTensorSemiringOps.tensorAxpy_spec]
rw [Vector.tensorAxpy_eq_map']
rw [Vector.getElem_mapFinIdx]
have hj : i ∈ (Layout.id h(n)).rangeNat := FinHTupleMap.mem_rangeNat_eval
simp [hj, FinHTupleMap.rangeNatInv_eval]
```

This avoids arbitrary existential witnesses and avoids proof-term mismatch from hidden `if` branch
proofs.

## Implementation Order

1. Prove `Fold.fold_eq_vector_map'`.
2. Add `FinHTupleMap.indexFun` and `FinHTupleMap.tupleFun`.
3. Add injectivity/range/inverse bridge lemmas between those functions and `map.Injective`,
   `map.rangeInv`, and `map.rangeNatInv`.
4. Add primed vector tensor algebra theorems using `fold_eq_vector_map'` and the bridge API.
5. Rewrite `Interfaces/TensorAlgebra/Lawful*Ops.lean` full-get lemmas using the primed vector
   theorems.
6. Keep old `*_eq_map` theorems for compatibility, but prefer primed theorem forms downstream.
